# Preview profiling

[Results from 22 October 2026](2026-10-22.md) compare PNG/SVG before and after the improvements, including kernel peak memory.

The suite runs real `TexpressoSession` instances against a local headless engine.
It uses TeX Live and installed `lipsum`, `geometry`, and TikZ packages. No downloads,
Tectonic, SDL windows, or VS Code window launches are involved.

```sh
npm run profile:preview -- --binary /path/to/texpresso \
  --output artifacts/profile-new --pages 1,10,100 --repeats 5 --width 1600
```

Use a new output directory. PNG and SVG alternate their order between repetitions.
Each repetition starts a fresh native process; OS/package/font caches are warm.
Do not run multiple benchmark jobs or builds concurrently when collecting results.
The default raster is 1600 pixels wide (approximately an 800 CSS pixel preview
at device pixel ratio 2). Native raster pixel limits still apply.

The fixtures have one, ten, or one hundred explicit pages. Sparse pages use one
`lipsum` paragraph, dense pages use five, and packed pages use eight (about 90% of the text area). The TikZ documents contain a 625-circle,
625-segment drawing plus prose on the first, middle, and last pages; intervening
pages contain prose. This tests long documents with expensive figure pages
without conflating document length with hundreds of identical complex figures.

The operations include:

* Startup through receipt of the first complete binary frame, including capability
  probing and root-buffer synchronization.
* Five exports from the retained current-page display list.
* A new next page, a jump to the last page, and visits to already compiled pages.
* Three literal text substitutions at the start of the first, middle, and last
  pages, and three curve-control-coordinate substitutions on each TikZ page.
* Revisiting the last page after editing the first, exposing incremental rollback.

Raw observations are in `runs.jsonl`; `summary.json` contains nearest-rank p50/p95
values. Observations from repeated edits within one process are correlated; the
five fresh-process startup samples are a small sample, not a population estimate.
Generated fixtures, exported images and memory traces stay under ignored
`artifacts/`. The compact committed results/report identify the measured inputs.
`--exports N --exports-only 1` restricts work to startup and retained-list export
for resolution/encoder microbenchmarks.

An engine built from this repository's profiling changes recognizes
`TEXPRESSO_PROFILE=1`. It writes JSON timing records to stderr for DVI display-list
creation, annotation serialization, SVG preflight/export, PNG drawing/color/encoding,
and pipe writes. The harness enables it automatically. Timing records do not
change the binary protocol. They are disabled during normal extension use.

On macOS the harness builds a small local sampler with Xcode's compiler. Every
50 ms it reads native task RSS, physical-footprint accounting, CPU counters and
the kernel lifetime peak footprint through `proc_pid_rusage` (v4), limited to
the process group it launched. It records
the viewer and XeTeX snapshot workers separately. Summed task RSS/footprints are
**not** deduplicated physical memory after copy-on-write forks. They must not be
reported as unique RAM usage. Sampled instantaneous peaks can miss brief allocations; the separate kernel
lifetime-peak counter retains them. Sampler timestamps use their own monotonic
clock; compare trace-relative time rather than assuming the same origin as
Node timestamps.
The Node memory values include the profiler's retained observations; they are
not an isolated measurement of the VS Code extension host.

A focused edit-position probe moves the literal text marker after the TikZ
figure and prose, while preserving the dense drawing:

```sh
npm run profile:preview -- --binary /path/to/texpresso --output artifacts/profile-tail-new \
  --pages 10 --kinds tikz --repeats 3 --edit-location after-figure --text-only 1
```

`compare-images.cjs BEFORE AFTER sparse,dense,tikz` compares each RGB pixel of
real exported pages and checks that SVG remains byte-identical. It accepts only
the opaque, unfiltered 8-bit RGB/grayscale PNGs generated by these writers.

## Browser stage

```sh
TEXPRESSO_BINARY=/path/to/texpresso npm run profile:preview:browser -- artifacts/profile-browser-new
```

The optional `TEXPRESSO_PROFILE_KINDS`, `TEXPRESSO_PROFILE_REPEATS`, and
`TEXPRESSO_PROFILE_START_DELAY_MS` environment variables select a focused browser
probe and allow UI inspection to settle before measurement. For a clean repeat,
collect an extra warm-up pair and exclude that pair explicitly in the analysis.

Open `http://127.0.0.1:9383` in a browser and press **Run preview profiles**.
This dashboard uses the production controller and webview assets, with the VS Code
image constraints and dark theme. A local HTTP/SSE bridge replaces VS Code's
`postMessage` IPC and transports binary frames separately from metadata.
The result explicitly records actual DPR, requested image dimensions, decode time,
HTTP transfer time and the time until two animation frames after the decoded image
is swapped. This last value is a paint opportunity, not a GPU completion timestamp.
Action-to-paint-opportunity values include the bridge and UI scheduling; they are
not measurements of Electron/Remote SSH IPC or production VS Code's total memory.

A separate canvas draw/readback probe at the visible page size helps expose SVG
rasterization cost. Readback includes synchronization/copy costs and is not
additive to the action timings. No browser/GPU memory total is inferred from the
encoded image size. SVG image geometry and raster caches are browser-owned;
outlined SVG is not inherently free of raster memory.

Each of the four page-content cases runs in both codecs, alternating order over
five fresh native sessions per case. The browser suite uses ten-page fixtures;
the native suite covers the document-length matrix. Use Ctrl-C to close the server
and its current engine; keep the results directory for later comparisons.

## Caching and SVG update experiments

The [caching follow-up](2026-10-22-caching.md) measures immediate page revisits,
identical output after undo, SVG ID stability, patch sizes and an experimental
retained SVG DOM. It includes reproduction commands and a measurement snapshot.
The production preview now caches exported pages and decoded images; SVG DOM
patching remains an isolated experiment.
